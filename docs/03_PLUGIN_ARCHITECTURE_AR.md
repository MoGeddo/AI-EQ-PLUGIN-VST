# معمارية الـVST3 — `AEQ Standard`

الهدف: بلجِن يقرأ صوت المايك، ويطلّع صوت قريب من «العيلة» اللي درسناها، **بشكل قابل للقياس والتحقق**، مش صندوق أسود بيخمّن.

مبني على نتيجة الدراسة الأساسية: **الـEQ المطلق غير قابل للاستخراج، لكن الفرق بين صوتك ومنحنى الهدف قابل للقياس بدقة** → فالمنتج الصح هو **target-matching**، مش «استنساخ إعدادات».

---

## 1. المبدأ الحاكم (قرار تصميم مش قابل للنقاش)

```
صوت داخل → تحليل (3–10s) → فرق عن الهدف → حل EQ تصحيحي محدود → تنفيذ DSP → خرج
```

ثلاث قواعد:
1. **سقف التصحيح ±6 dB** لكل باند، وعدد الباندات ≤ 10. (فوق كده بنبقى بنعمل صوت تاني، مش بنظبط صوت).
2. **مفيش موديل عصبي في المسار الصوتي.** كل حاجة DSP متجه (deterministic) → قابلة للتفسير والاختبار والـA/B. الـML لو دخل، يدخل في مرحلة **توصيف الإدخال** فقط (اختياري، مرحلة 3).
3. **كل بارامتر ليه مرجع رقمي من الدراسة** (جدول 4 في `02_TARGET_AND_PRESETS_AR.md`). مفيش «قيمة حلوة».

---

## 2. سلسلة المعالجة (Signal chain)

```
┌──────────────────────────────────────────────────────────────┐
│ 1. Input trim + DC/rumble watch                              │
│ 2. Adaptive HPF        24 dB/oct, default 170 Hz             │
│ 3. Match EQ            6–10 bands, ±6 dB cap, Q 0.4–2.5      │
│ 4. Resonance guard     dynamic narrow cuts (4.3k cluster)    │
│ 5. De-esser            band-split 5–10k, dyn, thr from study │
│ 6. Tone macros         PC1 (warmth↔presence), PC2 (body↔air) │
│ 7. Space (optional)    send (−14 dB) + LP colour @6 kHz      │
│ 8. Output trim + LUFS-matched A/B                            │
└──────────────────────────────────────────────────────────────┘
```

### 2.1 التحليل (offline thread، مش في المسار الصوتي)

| خطوة | التفاصيل |
|---|---|
| إطار القياس | STFT 8192، هوب 2048، Hann، على 48 kHz (نفس كود `analysis/aeq/spectral.py`) |
| VAD | RMS + spectral flatness على 10ms، يستبعد الصمت والتنفّس |
| LTAS | متوسط قدرة على الشبكة اللوغاريتمية 96 نقطة/أوكتاف |
| تسوية | 0 dB عند 1 kHz، ثم مقارنة بالهدف في نطاق 100 Hz–14 kHz |
| الثقة | الانحراف المعياري بين الفريمات → لو عالي، نقلل السقف (auto-safety) |
| الزمن | نافذة تعلّم 3–10 ثواني صوت فعّال، تحديث كل 500ms |

**نقطة مهمة:** التحليل بيتجاهل الصمت، وإلا الـLTAS هيتلوّث.

### 2.2 حل الـEQ (نفس الخوارزمية اللي في الريبو)

`analysis/aeq/voicemodel.py::fit_parametric` هي المرجع (Python)، والنسخة C++ هي:

1. ضع باند على أكبر انحراف متبقٍ (greedy placement).
2. احسب Q من عرض نصف البروز.
3. تحسين مشترك بـ Levenberg–Marquardt مع loss = soft-L1 (مقاومة للـoutliers).
4. قيّد النتيجة: `|gain| ≤ 6 dB`، `0.4 ≤ Q ≤ 2.5`، ورفض أي باند تحت 100 Hz (يُحوّل لـHPF).

النتيجة نفسها بتتحوّل لـ **RBJ biquads** — نفس معادلات `_rbj()` في الريبو، عشان تحليل بايثون وC++ يطلعوا نفس المنحنى بالمللي‑ديسيبل (فيه اختبار تكافؤ في مرحلة البناء).

### 2.3 HPF ذكي

- الـcorner الافتراضي **172 Hz** (median الكوربس).
- يتعدّل مع الـmedian F0 المقاس: `fc = clamp(0.55 × F0_median, 90, 200)`.
  سبب: لو المغني باس، 172 Hz ممكن ياكل الأساسي.
- الميل 24 dB/أوكتاف (2× biquad) — الكوربس بيقطع بحدّة.

### 2.4 De-esser (ديناميكي، مش ثابت)

- الحقيقة المقاسة: median −10.2 dB لكن **p90 −2.6 dB** → يعني متوسط كويس بس فيه قمم.
- التصميم: band-split عند 5 kHz، كشف على طاقة 5–10 kHz، gain reduction ناعم (attack 1ms، release 80ms) بحد أقصى 6 dB.
- ربطه بالـ**sibilance index** المحسوب حيًّا = نفس المعادلة المستخدمة في الدراسة (طاقة 5–10k ÷ 1–4k).
- **ما ينفعش** يبقى static notch، لأن الـdip الثابت عند 4.3 kHz اللي لقيناه في الميكسات هو **ناتج ميكس/مايك** مش حاجة تتحقن في صوت خام.

### 2.5 مقابض الذوق (الميزة الفارقة)

من PCA: 44% من الفرق بين الأغاني على PC1، و23% على PC2، وكل واحد متصدّر كبريست EQ حقيقي.

| مقبض | المدى | الخريطة |
|---|---|---|
| **Warmth ↔ Presence** | −1…+1 | منحنى PC1 × (`1/3` … `1`) — مش كامل عشان مايبقاش مبالغ |
| **Body ↔ Air** | −1…+1 | منحنى PC2 × معامل |
| **Standard** | 0…100% | نسبة تطبيق الـmatch EQ |

ده معناه: المستخدم بيختار **مكانه** جوه عيلة الصوت، مش بيختار «صح/غلط».

### 2.6 A/B عادل

مقارنة بدون loudness matching = تضليل. فيعمل الـVST: يحسب LUFS للـdry وللـwet (BS.1770-4، نفس كود `loudness.py`) ويعمل **gain compensation** عشان الـA/B يبقى على نفس المستوى.

## 4. بوابات القبول (Acceptance gates)

على طريقة `unlazy`: **اكتب معيار النجاح قبل ما تكتب الكود**، وكل بوابة لازم تعدّي بأمر قابل للتشغيل.

| # | البوابة | المعيار |
|---|---|---|
| G1 | تكافؤ الـbiquad | C++ وPython: أقصى فرق في الاستجابة < 0.01 dB حتى 20 kHz |
| G2 | دقة الـsolver | يركّب منحنى هدف معروف بـ RMS < 0.5 dB |
| G3 | التقارب للهدف | صوت اختبار بعد المعالجة: LTAS على مسافة < 1.5 dB من الهدف في 100 Hz–10 kHz |
| G4 | الثبات | 3 تشغيلات على نفس الإدخال → نفس الاستجابة ±0.05 dB (deterministic) |
| G5 | صفر ضرر | مفيش aliasing: THD+N < −90 dB على sine 1 kHz عند 0 dBFS |
| G6 | الزمن الحقيقي | CPU < 3% على 48 kHz/الستيريو لـ8 باندات (نواة واحدة) |
| G7 | صفر latency مضاف | المسار Audio كله minimum-phase، والتحليل offline |
| G8 | الـA/B عادل | فرق اللاودنس بين dry وwet < 0.1 LU |
| G9 | اختبار أعمى | 10 ملفات غناء مختلفة، المستخدم يختار wet في ≥ 7 (دليل إنه مفيد فعلاً) |

**G9 هو البوابة الحقيقية.** الباقي هندسي؛ ده اللي بيقول إن المنتج بيعمل حاجة الناس عايزاها.
